# 肉包 iOS Harness（2026-11-08）

## 当前实现

当前 IPA 已正式接入 AgentRunKit 核心库（固定提交 a7ac823ca42d4ecff386a83c10a44a97bd391cdb），未引入其 MLX/FoundationModels 推理 target。

- `iPhoneUse/Model/PhoneHarness.swift`：AgentRunKit 驱动任务循环、串行手机工具、不限制累计 token 用量（仍记录用量）、用户决定的步数扩展、45 秒普通工具超时、工具审批和检查点。
- `iPhoneUse/Model/ModelGateway.swift`：SwiftOpenAI 负责兼容模型协议；DeepSeek 使用非思考模式。仅对 429/502/503/504 模型响应有限重试，不重放手机动作。
- `iPhoneUse/Agent/PhoneAgent.swift`：保留任务界面状态、日志、截图证据、停止和问答；原手写 for-step 模型循环已移除。
- `DeviceSession` / `idevice-patch/probe.rs`：原有 CoreDevice 驱动负责手机自身截图、触控、输入和启动应用。

## 审批与恢复

`confirmed_action` 通过 AgentRunKit approval handler 请求用户确认，拒绝后不执行。审批返回目标应用后，比对新旧缩略图，页面差异较大即拒绝执行。这个像素检查只是保守的页面变化检测，不是语义证明。

普通 `tap/type` 的业务含义仍需要模型识别，因此尚不能宣称所有发布、回复或账号操作都受到不可绕过的强制审批。无人值守写账号流程不在当前验收范围。

检查点位于手机 Application Support/Harness，每轮工具执行结束后保存；恢复入口在“设置→任务执行→恢复上次中断任务”。检查点不保存 API Key 和截图附件，并排除系统备份。恢复要求同一模型和接口，重新截图；中断恢复不重放已完成工具。已完成任务收到新的用户消息时，使用 SDK 的 history 入口启动同一会话的新一轮，首次网络请求前也保存用户消息，带入已保存的工具结果与总结；不会把完成检查点直接 resume 成旧结果。每次新追问使用设置的初始步数，达到后仍由用户决定是否增加50步。

动作完成与检查点写入不是原子事务；若恰好在二者之间崩溃，需根据新截图核对，不能保证外部动作恰好执行一次。恢复能力不能延长 iOS 分配给应用的后台运行时间。检查点暂未设置自动清理上限。

## 验证

83 项离线测试通过，覆盖协议、串行动作、审批、取消、中断恢复、主模型接管、任务清单、PDF 参数、逐卡问答、100+50步数决策、完成后续聊与旧会话隔离、ASR gzip 与响应解析。

真机 iPhone 17 Pro Max / iOS 27.0.1，DeepSeek Flash：新 AgentRunKit 循环 9 步计算 23×17=391，正常结束；日志含 `harness: AgentRunKit` 标记。此前计算器 12×13=156 为迁移前对照，不应混作迁移版证据。

蜂窝连接修复：先实际尝试本机连接，再按需调用用户已添加的蜂窝连接助手；连接失败也恢复蜂窝数据，不再仅凭网络类型拒绝。目标手机助手已成功运行，用户反馈小红书任务正在执行；尚未单独完成退出应用后的纯蜂窝冷重连对照测试。其余未完成：拔线后冷重连、中文输入、真机中断恢复及审批交互。手机原生任务执行已经确认，Mac 只负责安装、首次启动参数和读取验证日志。

## 比较结论

用户在 Wi-Fi 关闭、蜂窝开启的条件下准备测试。实际探测确认 10.7.0.1 路径失败；实验性的 127.0.0.1 连接被对端重置，实验代码已撤回。上游同类问题：https://github.com/jkcoxson/LocalDevVPN/issues/31 。

手机配置已确认 `usesCellularShortcut=true`，用户反馈自己的小红书任务在运行。这个结果证明助手路径已经在目标设备建立连接，不能外推为所有网络/iOS 版本都免切换。应用不直接改系统网络设置，首次快捷指令添加仍需用户确认。

加固版还记录蜂窝恢复待办，若应用中断，下次打开优先恢复蜂窝；助手取消、连接失败及恢复未确认均有明确结果。15 项离线测试通过，覆盖无需切换的直接成功、恢复动作顺序、失败/回调丢失时恢复，以及未安装助手不改变网络。加固版 IPA 另存，避免安装时打断用户正在执行的任务。

## 输入与视觉定位更新

统一 CoreDevice 剪贴板写入/回读与 UniversalHID 组合键粘贴，移除 ASCII 物理按键拼字路径。增加 `replace_text`、`press_key`、本机 OCR/临时文字 ID 和可选 `tap_target`（TypeSafe JEV）。工具回执明确区分剪贴板、指令提交、OCR 提示和未验证的原生输入框值。

早期离线测试覆盖旧有运行流程及区域 OCR 证据、工具分离、JEV 请求和响应、非法框/低置信度/目标不存在时拒绝、编号目标校验、中间目标不能直接结束整项任务、未提供的工具不执行、结构化询问和待答复保存，以及 HTTP 失败不重试。SwiftPM 测试不覆盖 Rust FFI 的真机行为。实现细节与官方接口见 docs/JEV.md；真机结果单独记录在 output/VALIDATION.txt。

新增真机验收：手机端 JEV 合成图片定位测试成功；小红书 4 步输入任务成功，但未出现权限弹窗；肉包本身的最小验证页主动触发真实粘贴权限框，本机 OCR + CoreDevice 触控自动点击允许，随后原生输入框文字精确比对通过。首次设置应用中的允许按钮由用户点击，不作为自动确认依据。专用输入法方案未实施。

## JEV 逐步执行

AgentRunKit 仍拥有任务循环。启用后主模型通过 `set_plan` 提供剩余动作和可见完成条件；JEV 优先用纯文字 Choice 选择本帧 OCR 编号，无法定位时直接交回主模型；主模型保留全部已注册工具，可显式调用图片定位工具。已提交步骤不会直接重放；不确定时回到主模型重新规划。完成判定另行执行，若计划有 `expected_text`，本机 OCR 也必须精确匹配。此路径没有竞速或完整停滞检测；到达初始100步后通知并询问用户是否增加50步，不擅自结束。

地图复杂任务暴露了中间目标过早结束的问题：旧版到达门店详情就返回 done，未完成步行路线。因此该轮不计通过。修复后 JEV 只返回本段计划的观察结果，主模型必须核对完整原始目标、规划剩余步骤并汇报所需事实，才可结束；已新增多阶段回归测试。

## 手机内询问与通知

`ask_user_question` 支持普通文字，或通过 `questions_json` 提供 1-3 项问题、每项最多 6 个选项。卡片不预选、不自动提交；始终支持自由输入，答复由用户本人在肉包提交。询问通过 AgentRunKit 无动作超时的等待通道处理，普通手机动作仍为 45 秒；取消等待不执行后续动作。

待答复问题和已提交答复保存在手机 Application Support/Questions，排除备份并受数据保护。重开应用显示未完成的卡片；提交后优先恢复原检查点，没有检查点时带上用户已提交的答复重新规划。草稿输入尚不跨进程保存；外部动作与检查点仍不是原子事务，恢复不能保证恰好执行一次。

询问时申请系统通知授权并发出本地通知，点击返回同一问题卡片；锁屏通知不包含任务内容或答复。未授权、提醒关闭或发送失败会在卡片提示。通知提交成功与实际显示不同，系统专注模式、通知设置、权限和应用生命周期可能影响送达。通知诊断仅记录问题 ID、事件、时间和送达计数，不含问题正文或答案。真机通知和点击恢复应另行验收。

手机端记录调用数、回退数和各段时间。iPhone 17 Pro Max / iOS 27.0.1 同一计算器任务单次对照：JEV 完成 23×17=391，主模型 4 次、JEV 15 次、回退 2 次、动作 8 次，总计 36.46 秒；干净的主模型对照 9 次、动作 8 次、无恢复，总计 35.64 秒。JEV 请求合计 5.79 秒，主模型对照请求合计 12.13 秒；截图和 OCR 等开销抵消了模型时间收益。这是单次任务实测，尚未证明整段任务加速。后续用户将测试设备切换为 iPhone 15 Pro Max，不能将不同设备的耗时直接作为同机加速结论。


## 同一会话、原生文件与语音（2026-11-08）

RunRecord 保存会话身份和任务目录。完成后的发送继续所选会话，保留聊天记录、工具结果、截图证据和任务进度；新建对话才清空。历史版本无目录索引时，用该会话自己的文本记录回填，不使用其他会话的 latest 检查点。新一轮不继承之前的工具审批授权，不自动重放旧动作。

模型使用 update_task_progress 持久记录所有平台与事实；尚未完成的清单或尚未生成的所需 PDF 会阻止 done 成功，并反馈给主模型。create_pdf_report 使用本机 UIKit 排版，对 evidence_id 查验本会话截图，文件在 Documents/Reports；新报告使用新文件名，旧版保留。任务文件页提供 QuickLook 和系统分享。iPhone15 Pro Max 已实际完成三平台查询并产出11页图文报告，价格属于当时可见报价与附带条件，不等同于最终结算保证。

语音使用独立 ASR 配置，不依赖主模型提供商。火山引擎路径使用用户文档中已验收的 /api/v3/sauc/bigmodel、X-Api-Connect-Id、16kHz PCM 与 gzip 二进制帧；未混用新版 bigmodel_async 协议。Key 仅保存在手机 Keychain，一次性导入后删除导入文件；音频内存转换并直连 openspeech.bytedance.com，不经过 Mac。iPhone15 Pro Max 合成 PCM 真机识别准确，耗时3.33秒；麦克风权限与真人录音仍需正常使用中验证。


### 续聊与流式语音真机补验

iPhone15 Pro Max 在已完成的比价会话内继续要求另存摘要：主模型沿用历史价格与截图，create_pdf_report 生成5页摘要版；原11页报告仍在。主模型仅2次决策，无重新搜索。空 assistant.tool_calls 数组会被兼容接口拒绝，现已序列化为省略该字段，模型 HTTP 错误也显示具体状态与已脱敏原因。

语音改为录音过程中持续发送 PCM 帧，服务端累积修订直接替换输入框识别片段，不重复追加。结束录音和长按松手均只保留草稿，不自动发送；延迟的最终识别不会覆盖手动修改。真机合成音频收到13次递进文本、最终准确、3.50秒，界面截图确认识别文字仍在可编辑输入框。真人麦克风端到端测试尚需用户实际说话；此结果验证了真机 WebSocket、流式响应及输入框更新。

中断提示仅在对应会话显示，可关闭并持久记住；关闭不会删除检查点，历史“继续任务”入口仍可用。其他对话、新对话、设置及文件页不显示此提示。


### 待答复恢复与停滞接管

问题保存 conversationID、taskFolder 与当前轮请求。应用中断后，提交答复只写回原会话检查点，保留历史与用户纠正；缺少原检查点时保留答复并提示，绝不拼接最早任务启动新会话。首个模型请求前保存用户消息；重启恢复上次打开的会话。恢复答复作为明确的历史问题与用户答复交给主模型，先看新截图，不假定旧动作是否成功。离线回归覆盖另一个任务已成为 latest 后仍回到原问题。

连续4次 UI 尝试后，裁去状态栏与底部指示器的灰度缩图、OCR 文本均没有明显变化时，暂停旧 JEV 计划，携带最近动作与新截图交给主模型。主模型保留全部工具；观察到变化前不再让 JEV沿用计划。规划和生成报告不计为失败点击。停滞信号有误判可能，不表示动作一定未送达，不自动重放或停止。

结束前由同一个主模型额外核对最新请求、用户纠正与当前证据；未完成时返回原任务继续或询问用户，避免把“文件已生成/已预览”当成“已发送微 x”。这仍依赖模型正确理解画面，不能保证任何 App 的发送结果。此前实际卡住任务记录为 main=29/jev=0，微 x发送未完成；不计入成功验收。

PDF 预览添加明确的右上角“完成”与左侧系统分享，保留下拉关闭。iPhone15 Pro Max 已实际打开5页摘要、点击右上角完成，截图确认回到任务文件列表。


## 两次定位失败后的多模态恢复（2026-11-08）

依据用户要求，连续两次点击未见进展，或两次定位未返回可靠目标，就暂停旧 JEV 计划并禁止当前画面继续 tap/tap_text/tap_target/long_press/set_plan。由同一个主模型选择 locate_visual_target，独立请求只提供图片和目标描述，不提供 OCR；定位实际控件的可点击区域，尤其不能把图标下的文字框视为控件。

定位本身不触控。返回的归一化框必须通过范围、置信度和 UUID 验证，tap_visual_target 使用一次即消费；新截图变化会使目标失效，实际触控前还会重新截图比对。失败交回主模型，可重新观察、换路线或问用户，不自动回放点击或结束任务。发布/发送仍必须 confirmed_action 并引用 arguments.visual_target_id 进行审批。持续无变化会维持视觉恢复状态；观察到实际变化才解除旧坐标禁用。

参考源码的具体区别：
- [iPhone Use](https://github.com/EliotAndres/iphone-use-app/blob/main/iPhoneUse/Agent/PhoneAgent.swift) 原始循环是截图→模型→工具，并没有本项目的“两次失败”策略。
- [Mobilerun](https://github.com/droidrun/mobilerun/blob/main/mobilerun/agent/droid/droid_agent.py) 将 Executor 结果反馈给 Manager；本项目继续让主模型决定恢复。
- [Mobile-JEV](https://github.com/droidrun/mobile-jev/blob/main/scripts/mobile-agent/agent.mjs) 用画面指纹与动作签名检测重复、不重试结果未知的变更；其直接 stuck 结束逻辑未照搬到本项目。
- [Browser Use / Jev Ultrafast](https://github.com/browser-use/jev-ultrafast) 的编号来自实际 DOM 控件引用，并校验遮挡与新鲜度；本项目 OCR 只有文字框，不能等同于 DOM/AX 控件。

67项离线回归覆盖两次失败禁用旧点击、主模型图片请求不含 OCR、坐标框校验、一次性目标及页面变化失效。真机视觉能力探针仅使用合成彩色图形，不操作其他应用、不发送消息。

真机补验：iPhone15 Pro Max 通过当前配置的主模型执行无文字合成彩色图形定位，返回红色矩形中心，归一化中心误差约0.00369，置信度0.97；请求未提供 OCR，也没有执行任何触控。这证明该次主模型图像输入与定位链路有效，不代表微 x等任意实际页面均能准确定位。待答复问题更新前后内容一致。


## 通用授权与文件交互补验（2026-11-08）

确认卡片返回结构化 answers，旧代码直接与纯文本“确认”比较，导致明确确认被误判取消。现由 PhoneApprovalDecision 统一解析卡片/纯文本；批准、拒绝与补充意见分别处理，补充意见交还主模型，不循环弹同一确认。审批卡显示操作描述和确认/取消选项，不展示原始工具 JSON。

PhoneAuthorization 为全部 confirmed_action 共用授权账本：绑定原操作说明、应用、动作和非坐标内容，重新定位可沿用授权；更换内容、应用或真实用途须新授权。状态 approved→dispatched→submitted/unknown 持久保存；只有确定未发出的 staleScreen/参数错误可恢复 approved。已提交或送达未知的动作不能重放，改写说明也不会自动触发另一次相同授权。confirmed_action 回执向主模型明确返回 owner_approved、authorization_id 和待核对的提交状态。重启时已提交的卡片答复也可恢复授权。

普通 tap/tap_text/long_press、视觉目标、JEV 点击和聊天 Return 共用最终动作标签检查；发现可见“发送/发布/删除/支付/提交/收藏”等控制时，需走 confirmed_action，不能在授权被拒绝后用普通点击绕过。此检测基于 OCR，是保守门禁；缺失或误识别标签、无文字控件仍需模型正确理解，尚不是覆盖所有 UI 变更的语义强制证明。
