# JEV 与输入通道

## 作用边界

AgentRunKit 继续负责串行执行、审批、停止、步数限制和检查点。启用“JEV 逐步执行”后，主模型通过 `set_plan` 提供完整的剩余动作计划；JEV 根据每张新截图判断当前步骤是否就绪，定位目标，并核对本段计划的完成条件。计划完成必须交回主模型核对原始任务的全部要求，不能把门店详情等中间目标当成整项任务完成。主模型始终保留全部已注册工具。JEV、OCR、输入核对或工具失败均交回主模型，由它决定单步操作、重规划或询问用户。已知 bundle ID 的启动应用由系统接口按计划执行，不要求 JEV 先找到图标。

本机 Apple Vision OCR 为每张截图附带文字框和临时 ID。`tap_text` 可直接使用当前帧 ID 点击文字；这些只是视觉观察，不是系统无障碍树，无法确认原生第一响应者或读取控件实际值。

`tap_target` 在需要时把当前 JPEG 和目标描述发送到 TypeSafe 的 `/v1/systemone`。同一次请求包含目标存在且唯一可点的 Noul 与目标位置 Box；采用 multipart，只上传一份截图，设置 `TypeSafe-Danger-Zone-Images: true`。两项均达到本项目实验阈值 0.85、框合法且页面未明显变化时才点击一次。阈值不是厂商准确率保证。不存在、不确定、超时或接口失败会返回未执行；动作开始后若传输失败则返回状态未知，要求重新观察，不重放动作。

Box 总会返回框，因此不能单独信任它。TypeSafe 官方把 Images/Box 标为实验能力。默认模型 `jev-latest`，Key 单独保存在 iPhone Keychain；可在设置→任务执行→JEV 视觉定位中关闭、更换 Key/模型和运行合成图片测试。关闭或未配置时不发 TypeSafe 请求。

JEV 快路径把 OCR 文字整理成当前帧编号候选表，通过纯 JSON Choice 选目标 ID；编号必须属于当前候选集，坐标由本机 OCR 框决定。识别结果按词拆分，避免一排按钮共用一个框。返回分布必须完整、有限、归一，且选项为最大概率。读界面实验门槛为所选概率至少 0.7、分布置信度至少 0.4，门槛不是正确率承诺。无法匹配文字候选时直接交回主模型，不自动再发图片请求。主模型可显式选择图片定位工具 tap_target，其门槛为 0.85。

已提交步骤不重复提供。主模型另给单一、可见的完成条件；JEV 检查该条件，若提供 expected_text，还须由本机 OCR 匹配完整文本。低置信度、计划外页面和接口错误回到主模型重新规划。连续两次定位点击未见进展或两次定位失败，就暂停旧计划并禁用旧文字编号和坐标。主模型使用独立的 locate_visual_target 图片请求重定位，再用一次性 tap_visual_target；图像变化使目标失效，不自动重复点击或停止。一般 UI 的四次停滞诊断仍保留。达到初始100步时通知并询问用户是否增加50步。普通动作的业务含义仍依赖模型判定；现有审批不是覆盖所有账号写操作的不可绕过闸门，JEV 不扩大授权。

OCR 候选不是 iOS 无障碍树，无法提供原生控件角色、焦点、遮挡状态或持久节点引用。编号每帧失效；观察后发生的页面变化仍可能导致错位，必须检查下一帧效果。

## 执行、恢复与耗时

- 设置中可分别开关 JEV 和逐步执行；关闭逐步执行时保留可选定位工具。未配置或停用 JEV 时不提供不可用的定位工具。
- 每帧本机 OCR，JEV 优先消费编号文字候选；截图保留作证据，文字路径不上传图片。复用临时 URLSession，减少逐步建连。
- `jev-run-metrics.json` 和任务历史记录主模型/JEV 调用数、回退数、动作数、模型时间、截图时间和 harness 总时间；不含 Key。耗时不含此前连接和配对准备。
- `jev-last-response.json` 仅记录最新的模型名、结构化判断和用量供诊断，不保存请求头或图片。
- JEV 的临时计划不单独持久化；恢复检查点时主模型根据新截图和工具历史重新规划剩余步骤，不直接重放旧计划。
- 保留手动停止、普通工具45秒超时；用户问答及步数扩展等待不受动作超时限制，累计 token 不设上限。

## 实践来源

- [Browser Use / Jev Ultrafast](https://github.com/browser-use/jev-ultrafast)：动态编号控件表，操作与目标在同一次请求分类，默认不发截图，DONE 另行验证。其 7.073 秒网页演示是单任务结果，不能外推到手机。
- [awlevin / typesafe-computer-use](https://github.com/awlevin/typesafe-computer-use/blob/main/docs/how-a-step-works.md)：Vision OCR + AX 候选、去重与邻行语义、近期动作、停滞检测和主模型交接。其 Mac 耗时是作者实测，不是本项目验收。
- [TypeSafe 官方说明](https://typesafe.ai/blog/jev-1-14)：图片与 Box 仍是实验能力，多模态可靠性低于纯文字，应拆成简单判断。[Fan-out](https://docs.typesafe.ai/patterns/fan-out) 建议把适用问题合并到同一请求，由代码选择相关答案。

本项目采用计划、编号目标选择与主模型显式视觉定位的组合。尚未取得通用 iOS AX 数据，也没有局部 OCR 缓存。当前已增加结构页面停滞检查与两次失败后的主模型图片定位，不能声称完整复现这些项目。

## 输入

中文、英文、Emoji 和多行文本统一通过 CoreDevice PasteboardService 写入，回读与待写文本一致后才发送一次系统粘贴。不读取或保存用户原有剪贴板；输入会替换系统剪贴板。组合键使用 UniversalHID 完整按住集合，退出时复位并移除本次创建的键盘。异常也执行清理，不重放粘贴。

- `type`：在已获得焦点的输入框光标处粘贴，或替换当前选区。
- `replace_text`：在已获得焦点的输入框全选后粘贴，不提交。
- `press_key`：Return、Backspace 或 Escape，不修改剪贴板。
- 兼容旧任务：`type` 的文本仅为一个换行时继续按 Return；多行文本整体粘贴。

可在输入工具中提供四个 `field_*` 像素参数，限定输入框区域的 OCR 比对。回执区分剪贴板已校验、粘贴指令已提交、OCR 区域匹配及原生控件值未验证。剪贴板回读不是输入框验收；OCR 可能漏字、混淆标点或无法读取密码/裁切区域。未识别到时要求看新截图，不能盲目再次输入。首次系统粘贴提示需正常处理。

## 粘贴权限框真机验证（2026-11-08）

按用户要求，将小红书“从其他 App 粘贴”从“允许”改为“询问”，截图确认勾选。随后完整 AI 任务 4 步输入 `肉包自动粘贴验证20261108`，未提交搜索或互动；该次没有出现授权框，不能当作自动确认权限的证据。此前设置应用的首次“允许粘贴”由用户手动点击，也不计为自动化证据。

为隔离验证，在肉包本身增加仅通过 `-pasteProbe YES` 启动的最小输入页。CoreDevice 先写入并校验合成测试文字，随后前台直接读取，实际触发“肉包想从 dtpasteboardd 粘贴”系统弹窗。手机端后台任务截图并用本机 OCR 定位精确的“允许粘贴”按钮，再通过 CoreDevice 触控点击，前台得到文字并比对控件内容。真机结果 `alert_clicked_by_driver=true`、`exact_field_value=true`；保存前后截图。检测只处理本次测试写入的 `dtpasteboardd` 来源，不匹配“不允许粘贴”。这是当前 iPhone 17 Pro Max / iOS 27.0.1 的受控测试，不是任意系统权限框都能自动处理的承诺。

最小验证页默认不显示；普通任务继续由模型根据新截图与 `tap_text`/`tap` 处理正常粘贴确认。用户要求验证成功后保留当前方案，未新增专用输入法或键盘扩展。新建硬件键盘后首个快捷键可能丢失，已增加连接后及全选后等待。全文替换尚未独立验收：早先设置应用测试实际追加；后续肉包测试的首段文字被权限框阻挡，不能将最终文字出现当作替换成功的证据。各应用仍需按截图检查输入结果。
